# Инструменты, способы и меры для обеспечения конфиденциальности данных

## I. Инструменты защиты данных

### Шифрование данных

#### Шифрование на диске (Data at Rest)

**Инструменты:**

- **BitLocker** (Windows Server)
  - Описание: Встроенное шифрование дисков Windows
  - Применение: Шифрование всего диска файлового сервера
  - Преимущества: Интеграция с Active Directory, прозрачное шифрование
  - Недостатки: Только для Windows

- **VeraCrypt**
  - Описание: Кроссплатформенное шифрование дисков
  - Применение: Шифрование отдельных разделов или контейнеров
  - Преимущества: Бесплатный, открытый исходный код
  - Недостатки: Требует ручной настройки

- **Azure Information Protection (AIP)**
  - Описание: Защита файлов на основе меток
  - Применение: Шифрование отдельных файлов с ПДн
  - Преимущества: Интеграция с Office, автоматическое применение
  - Недостатки: Требует подписки Microsoft 365

- **Database Encryption (для будущих БД)**
  - PostgreSQL: pgcrypto, Transparent Data Encryption
  - MySQL: InnoDB encryption
  - SQL Server: Always Encrypted, TDE

**Рекомендация**: BitLocker для файлового сервера + AIP для отдельных файлов

#### Шифрование при передаче (Data in Transit)

**Инструменты:**

- **TLS 1.3**
  - Описание: Протокол шифрования для передачи данных
  - Применение: 
    - Передача между 1С системами
    - Передача от лаборатории
    - Доступ к файловому серверу (SMB 3.0 с шифрованием)
    - Электронная почта (SMTP/TLS, IMAP/TLS)
  - Настройка: Внутренний PKI или Let's Encrypt

- **VPN**
  - Описание: Виртуальная частная сеть
  - Применение: Удалённый доступ к системам
  - Инструменты: OpenVPN, WireGuard, Windows VPN

- **SFTP/FTPS**
  - Описание: Безопасная передача файлов
  - Применение: Передача файлов от лаборатории
  - Инструменты: FileZilla Server, WinSCP

**Рекомендация**: TLS 1.3 для всех соединений + VPN для удалённого доступа

#### Шифрование в БД (Column-level Encryption)

**Инструменты:**

- **1С: Предприятие** (для текущей системы)
  - Встроенные механизмы шифрования конфигурации
  - Шифрование реквизитов через внешние компоненты

- **PostgreSQL** (для будущих систем)
  - pgcrypto для шифрования полей
  - Transparent Data Encryption для всей БД

**Рекомендация**: Использовать встроенные механизмы 1С + планировать миграцию на PostgreSQL с TDE

### Контроль доступа

#### Управление идентификацией и доступом (IAM)

**Инструменты:**

- **Active Directory (AD)**
  - Описание: Уже используется в компании
  - Применение: Централизованное управление пользователями
  - Улучшения: 
    - Внедрение групп безопасности по ролям
    - Регулярный аудит доступа
    - Политики паролей

- **Azure AD** (для будущих облачных сервисов)
  - Описание: Облачная версия AD
  - Применение: Управление доступом к облачным сервисам
  - Преимущества: Интеграция с Microsoft 365, MFA

- **LDAP**
  - Описание: Уже используется
  - Применение: Аутентификация в приложениях

**Рекомендация**: Улучшить использование AD + планировать Azure AD для облачных сервисов

#### Контроль доступа на основе ролей (RBAC)

**Инструменты:**

- **Windows File Server Permissions**
  - Описание: Встроенные права доступа Windows
  - Применение: Контроль доступа к файлам на общем диске
  - Настройка: Группы безопасности AD + NTFS права

- **1С: Предприятие**
  - Описание: Встроенная система ролей
  - Применение: Контроль доступа в 1С системах
  - Настройка: Создание ролей и назначение прав

- **Future: Keycloak** (для новых систем)
  - Описание: Open-source IAM решение
  - Применение: Управление доступом к новым сервисам
  - Преимущества: Поддержка RBAC и ABAC

**Рекомендация**: Настроить RBAC в AD и 1С + использовать Keycloak для новых систем

#### Контроль доступа на основе атрибутов (ABAC)

**Инструменты:**

- **Apache Ranger**
  - Описание: Платформа для управления политиками доступа
  - Применение: Контроль доступа к Data Lake и будущим системам
  - Преимущества: Поддержка ABAC, интеграция с Hadoop

- **OPA (Open Policy Agent)**
  - Описание: Универсальный движок политик
  - Применение: Контроль доступа в микросервисах
  - Преимущества: Гибкость, декларативные политики

**Рекомендация**: Планировать использование для будущих систем

### Тегирование и классификация данных

**Инструменты:**

- **Microsoft Purview Information Protection (AIP)**
  - Описание: Решение для классификации и защиты данных
  - Применение: Тегирование файлов Excel, Word, PDF
  - Преимущества: Интеграция с Office, автоматическое применение

- **Apache Atlas**
  - Описание: Платформа для управления метаданными
  - Применение: Тегирование данных в Data Lake
  - Преимущества: Data Lineage, интеграция с Hadoop

- **Varonis Data Classification**
  - Описание: Автоматическая классификация данных
  - Применение: Обнаружение и тегирование ПДн
  - Преимущества: Автоматическое обнаружение, мониторинг

**Рекомендация**: AIP для файлов + Atlas для Data Lake

### Аудит и мониторинг

#### Логирование и аудит

**Инструменты:**

- **Windows Event Log**
  - Описание: Встроенное логирование Windows
  - Применение: Логирование доступа к файлам
  - Настройка: Включение аудита доступа к файлам

- **SIEM системы**
  - **Splunk**
    - Описание: Платформа для анализа данных
    - Применение: Централизованное логирование и анализ
    - Преимущества: Мощная аналитика, корреляция событий
    - Недостатки: Дорогое решение

  - **ELK Stack (Elasticsearch, Logstash, Kibana)**
    - Описание: Open-source решение для логирования
    - Применение: Централизованное логирование
    - Преимущества: Бесплатный, масштабируемый
    - Недостатки: Требует настройки и поддержки

  - **Graylog**
    - Описание: Open-source платформа для логирования
    - Применение: Централизованное логирование
    - Преимущества: Проще чем ELK, хороший UI

**Рекомендация**: Начать с Windows Event Log + Graylog для централизованного логирования

#### Мониторинг безопасности

**Инструменты:**

- **Microsoft Defender for Endpoint**
  - Описание: EDR решение от Microsoft
  - Применение: Защита рабочих станций и серверов
  - Преимущества: Интеграция с Windows, обнаружение угроз

- **Wazuh**
  - Описание: Open-source платформа безопасности
  - Применение: Мониторинг безопасности, обнаружение инцидентов
  - Преимущества: Бесплатный, интеграция с ELK

- **OSSEC**
  - Описание: Open-source HIDS
  - Применение: Мониторинг файловой целостности
  - Преимущества: Бесплатный, лёгкий

**Рекомендация**: Microsoft Defender для Windows + Wazuh для дополнительного мониторинга

### Обфускация и обезличивание данных

#### Обфускация данных

**Инструменты:**

- **Delphix**
  - Описание: Платформа для управления данными
  - Применение: Создание обфусцированных копий для тестирования
  - Преимущества: Автоматизация, интеграция с БД
  - Недостатки: Дорогое решение

- **Informatica Data Masking**
  - Описание: Решение для маскирования данных
  - Применение: Обфускация данных для тестирования
  - Преимущества: Широкие возможности маскирования

- **Custom Scripts (Python)**
  - Описание: Собственные скрипты для обфускации
  - Применение: Простая обфускация для тестовых сред
  - Преимущества: Бесплатно, гибкость
  - Недостатки: Требует разработки

**Рекомендация**: Начать с custom scripts, при росте - рассмотреть Delphix

#### Обезличивание данных

**Инструменты:**
- **ARX Data Anonymization**
  - Описание: Open-source инструмент для обезличивания
  - Применение: Обезличивание данных для аналитики
  - Преимущества: Бесплатный, поддержка различных методов

- **sdcMicro (R package)**
  - Описание: R пакет для статистического обезличивания
  - Применение: Обезличивание данных для исследований
  - Преимущества: Бесплатный, статистические методы

- **Python библиотеки**
  - **Faker**: Генерация синтетических данных
  - **Presidio**: Обнаружение и обезличивание ПДн
  - **pandas**: Обработка данных для обезличивания

**Рекомендация**: ARX для обезличивания + Python для автоматизации

  - Применение: Хранение сертификатов для TLS

**Рекомендация**: HashiCorp Vault для on-premise + Azure Key Vault для облачных сервисов

  - Описание: Встроенное решение Windows

**Рекомендация**: Veeam для критических данных + Windows Backup для базовых бэкапов

## II. Меры защиты по потокам данных

### DFD01 - Регистрация пациента

**Этапы защиты:**

1. **Сбор данных от пациента**
   - TLS для передачи данных (если через веб-форму)
   - Валидация данных на стороне сервера
   - Логирование сбора данных

2. **Хранение в Excel**
   - Шифрование файла (BitLocker или AIP)
   - Тегирование файла (confidentiality:personal, sensitivity:high)
   - Контроль доступа (RBAC - только ресепшен)
   - Аудит доступа к файлу

3. **Создание папки пациента**
   - Шифрование папки (BitLocker)
   - Тегирование папки
   - Контроль доступа (RBAC)
   - Аудит создания папки

**Инструменты:**

- BitLocker для шифрования диска
- AIP для тегирования файлов
- Windows File Server Permissions для контроля доступа
- Windows Event Log для аудита

### DFD02 - Запись к врачу

**Этапы защиты:**

1. **Запрос на запись**
   - Валидация данных пациента
   - Проверка прав доступа
   - Логирование запроса

2. **Проверка расписания**
   - Контроль доступа к журналу (RBAC)
   - Аудит чтения журнала

3. **Запись в журнал**
   - Шифрование журнала (BitLocker)
   - Тегирование записи (confidentiality:personal)
   - Контроль доступа (RBAC)
   - Аудит записи

**Инструменты:**

- BitLocker для шифрования
- AIP для тегирования
- Windows File Server Permissions для контроля доступа
- Windows Event Log для аудита

### DFD03 - Приём пациента

**Этапы защиты:**

1. **Проведение приёма**
   - Контроль доступа к медицинской карте (RBAC - только врач)
   - Аудит доступа к карте

2. **Заполнение медицинской карты**
   - Шифрование файла карты (AIP)
   - Тегирование (confidentiality:medical, sensitivity:critical)
   - Контроль доступа (RBAC - только врач)
   - Аудит записи в карту

3. **Назначение анализов**
   - Шифрование реестра анализов (BitLocker)
   - Тегирование (confidentiality:medical, source:doctor)
   - Контроль доступа (RBAC)
   - Аудит назначения

**Инструменты:**

- AIP для шифрования и тегирования медицинских карт
- BitLocker для шифрования реестров
- Windows File Server Permissions для контроля доступа
- Windows Event Log для аудита

### DFD04 - Оплата услуг

**Этапы защиты:**

1. **Приём оплаты**
   - Шифрование данных ККМ (TLS для передачи)
   - Контроль доступа к ККМ (RBAC - только кассиры)
   - Аудит операций ККМ

2. **Обработка платежа**
   - Шифрование данных в 1С (встроенное шифрование)
   - Шифрование передачи (TLS/OLE)
   - Тегирование (confidentiality:financial, sensitivity:high)
   - Контроль доступа (RBAC - кассиры, бухгалтеры)
   - Аудит финансовых операций

3. **Учёт в Excel**
   - Шифрование файла (BitLocker или AIP)
   - Тегирование (confidentiality:financial)
   - Контроль доступа (RBAC)
   - Аудит записи

**Инструменты:**

- TLS для передачи данных ККМ
- Встроенное шифрование 1С
- BitLocker или AIP для файлов
- Windows File Server Permissions для контроля доступа
- Windows Event Log для аудита

### DFD05 - Результаты анализов

**Этапы защиты:**

1. **Получение результатов от лаборатории**
   - TLS для передачи от лаборатории
   - Валидация данных
   - Логирование получения

2. **Сохранение результатов**
   - Шифрование файла (AIP)
   - Тегирование (confidentiality:medical, sensitivity:critical, source:laboratory)
   - Контроль доступа (RBAC - врачи, пациенты - только свои данные)
   - Аудит сохранения

3. **Уведомление врача и пациента**
   - Шифрование почты (TLS)
   - Контроль доступа к уведомлениям
   - Аудит отправки уведомлений

**Инструменты:**

- TLS для передачи от лаборатории
- AIP для шифрования и тегирования результатов
- Exchange Mail Server с TLS для уведомлений
- Windows File Server Permissions для контроля доступа
- Windows Event Log для аудита
