# Список данных для защиты и методы защиты

## I. Классификация данных по уровню конфиденциальности

### Уровень 1 - Критически конфиденциальные (требуют максимальной защиты)

#### Медицинские диагнозы

- **Категория**: Медицинские данные (PHI)
- **Хранение**: Файлы в папках пациентов (PDF, JPG, Excel)
- **Передача**: По локальной сети, через Exchange Mail Server
- **Методы защиты**:
  - **Шифрование**: AES-256 для файлов на диске, TLS 1.3 для передачи
  - **Обфускация**: Не применяется (данные должны быть читаемы для врачей)
  - **Обезличивание**: Применяется для аналитики и BI (замена ФИО на хэш, удаление дат рождения)
  - **Контроль доступа**: RBAC - только врачи и медперсонал
  - **Аудит**: Полное логирование всех операций чтения/записи
  - **Теги**: `confidentiality:medical`, `sensitivity:critical`, `retention:permanent`

#### Результаты анализов

- **Категория**: Медицинские данные (PHI)
- **Хранение**: Файлы в папках пациентов, реестр анализов (Excel)
- **Передача**: От лаборатории, по локальной сети
- **Методы защиты**:
  - **Шифрование**: AES-256 для файлов, TLS 1.3 для передачи от лаборатории
  - **Обфускация**: Не применяется для рабочих данных
  - **Обезличивание**: Применяется для статистики (удаление идентификаторов)
  - **Контроль доступа**: RBAC - врачи, лаборанты, пациенты (только свои данные)
  - **Аудит**: Логирование доступа, особенно внешнего доступа от лаборатории
  - **Теги**: `confidentiality:medical`, `sensitivity:critical`, `retention:10years`, `source:laboratory`

#### История лечения

- **Категория**: Медицинские данные (PHI)
- **Хранение**: Файлы в папках пациентов
- **Передача**: По локальной сети
- **Методы защиты**:
  - **Шифрование**: AES-256 для файлов, TLS для передачи
  - **Обфускация**: Не применяется
  - **Обезличивание**: Применяется для исследований (полная анонимизация)
  - **Контроль доступа**: RBAC - только врачи и медперсонал
  - **Аудит**: Полное логирование
  - **Теги**: `confidentiality:medical`, `sensitivity:critical`, `retention:permanent`

#### Хронические заболевания

- **Категория**: Медицинские данные (PHI)
- **Хранение**: Файлы в папках пациентов, Excel-файлы
- **Передача**: По локальной сети
- **Методы защиты**:
  - **Шифрование**: AES-256 для файлов
  - **Обфускация**: Не применяется
  - **Обезличивание**: Применяется для статистики
  - **Контроль доступа**: RBAC - только врачи
  - **Аудит**: Логирование доступа
  - **Теги**: `confidentiality:medical`, `sensitivity:critical`, `retention:permanent`

### Уровень 2 - Высококонфиденциальные

#### ФИО + Дата рождения

- **Категория**: Персональные данные (PII)
- **Хранение**: Excel-файлы, файлы в папках пациентов, 1С:Бухгалтерия
- **Передача**: По локальной сети, через OLE, TCP/IP
- **Методы защиты**:
  - **Шифрование**: AES-256 для файлов, TLS для передачи, шифрование полей в БД
  - **Обфускация**: Частичная обфускация для тестовых сред (замена на тестовые данные)
  - **Обезличивание**: Применяется для аналитики (псевдонимизация с ключом)
  - **Контроль доступа**: RBAC - ресепшен, врачи, бухгалтерия (только для платежей)
  - **Аудит**: Логирование всех операций
  - **Теги**: `confidentiality:personal`, `sensitivity:high`, `retention:10years`, `pii:true`

#### Адрес прописки

- **Категория**: Персональные данные (PII)
- **Хранение**: Excel-файлы, файлы в папках пациентов
- **Передача**: По локальной сети
- **Методы защиты**:
  - **Шифрование**: AES-256 для файлов
  - **Обфускация**: Не применяется для рабочих данных
  - **Обезличивание**: Применяется для аналитики (удаление или обобщение до города)
  - **Контроль доступа**: RBAC - ограниченный доступ (только при необходимости)
  - **Аудит**: Логирование доступа
  - **Теги**: `confidentiality:personal`, `sensitivity:high`, `retention:10years`, `pii:true`

#### Финансовые данные (платежи, договоры)

- **Категория**: Финансовые данные + ПДн
- **Хранение**: 1С:Бухгалтерия, Excel, ККМ
- **Передача**: TCP/IP-OLE между ККМ и 1С, по локальной сети
- **Методы защиты**:
  - **Шифрование**: AES-256 для файлов, TLS для передачи, шифрование полей в БД
  - **Обфускация**: Не применяется (требуется для бухгалтерии)
  - **Обезличивание**: Применяется для аналитики (агрегация, удаление ПДн)
  - **Контроль доступа**: RBAC - кассиры, бухгалтеры, руководство
  - **Аудит**: Полное логирование всех финансовых операций
  - **Теги**: `confidentiality:financial`, `sensitivity:high`, `retention:5years`, `pii:true`, `pci:true`

## III. Детализация методов защиты

### Шифрование

#### Шифрование на диске (Data at Rest)

- **Алгоритм**: AES-256
- **Режим**: AES-GCM (для файлов), AES-CBC (для БД)
- **Управление ключами**: HSM или Key Management Service
- **Ротация ключей**: Ежегодно или при компрометации
- **Область применения**: Все файлы с ПДн и медицинскими данными

#### Шифрование при передаче (Data in Transit)

- **Протокол**: TLS 1.3
- **Сертификаты**: Внутренний PKI или коммерческие сертификаты
- **Область применения**: 
  - Передача между системами (1С, ККМ)
  - Передача от лаборатории
  - Доступ к файловому серверу
  - Электронная почта

#### Шифрование в БД (Data in Database)

- **Метод**: Column-level encryption для чувствительных полей
- **Алгоритм**: AES-256
- **Область применения**: 1С:Бухгалтерия, будущие БД

### Обфускация

#### Тестовые среды

- **Метод**: Замена реальных данных на синтетические
- **Область применения**: 
  - Разработка и тестирование
  - Обучение сотрудников
- **Инструменты**: Data masking tools (например, Delphix, Informatica)

#### Частичная обфускация

- **Метод**: Замена части данных (например, последние 4 цифры телефона на XXXX)
- **Область применения**: Отображение данных в интерфейсах, где полные данные не нужны

### Обезличивание

#### Псевдонимизация

- **Метод**: Замена идентификаторов на псевдонимы с сохранением ключа
- **Область применения**: Аналитика с возможностью восстановления связи
- **Хранение ключей**: Отдельное защищённое хранилище

#### Анонимизация

- **Метод**: Полное удаление идентификаторов
- **Область применения**: 
  - Статистика и исследования
  - BI-отчёты
  - ML/AI обучение

#### Агрегация

- **Метод**: Объединение данных в группы
- **Область применения**: 
  - Финансовые отчёты
  - Статистика по заболеваниям
  - Отчёты по зарплатам

#### Обобщение

- **Метод**: Замена точных значений на обобщённые (город вместо адреса)
- **Область применения**: Аналитика с сохранением полезности данных

## IV. Применение методов по этапам жизненного цикла данных

### Сбор данных

- **Шифрование**: TLS при передаче от источника
- **Контроль доступа**: Проверка прав на сбор данных
- **Аудит**: Логирование сбора данных

### Хранение данных

- **Шифрование**: AES-256 на диске
- **Контроль доступа**: RBAC/ABAC
- **Аудит**: Логирование всех операций
- **Резервное копирование**: Зашифрованные бэкапы

### Обработка данных

- **Шифрование**: Данные в памяти защищены (если возможно)
- **Контроль доступа**: Проверка прав на обработку
- **Аудит**: Логирование операций обработки

### Передача данных

- **Шифрование**: TLS 1.3
- **Контроль доступа**: Проверка прав получателя
- **Аудит**: Логирование передачи

### Удаление данных

- **Безопасное удаление**: Перезапись секторов диска
- **Аудит**: Логирование удаления
- **Проверка**: Подтверждение удаления из всех мест

## V. Специальные требования

### Медицинские данные

- **Дополнительная защита**: Двойное шифрование для критических данных
- **Изоляция**: Отдельные хранилища для медицинских данных
- **Срок хранения**: Согласно медицинским требованиям (обычно 10+ лет)

### Финансовые данные

- **Соответствие**: PCI DSS требования (если применимо)
- **Аудит**: Полное логирование всех финансовых операций
- **Резервное копирование**: Ежедневные зашифрованные бэкапы

### Данные для аналитики

- **Обезличивание**: Обязательное перед использованием в BI/ML/AI
- **Изоляция**: Отдельная среда для аналитики
- **Контроль доступа**: Ограниченный доступ к обезличенным данным
