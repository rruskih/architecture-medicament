# Механизм тегирования данных

## I. Структура тегов

### Формат тегов

Теги имеют иерархическую структуру и формат: `категория:значение`

### Основные категории тегов

#### 1. Конфиденциальность (confidentiality)

**Значения:**

- `confidentiality:public` - Публичные данные
- `confidentiality:internal` - Внутренние данные
- `confidentiality:personal` - Персональные данные
- `confidentiality:medical` - Медицинские данные
- `confidentiality:financial` - Финансовые данные
- `confidentiality:restricted` - Ограниченный доступ

#### 2. Чувствительность (sensitivity)

**Значения:**

- `sensitivity:low` - Низкая чувствительность
- `sensitivity:medium` - Средняя чувствительность
- `sensitivity:high` - Высокая чувствительность
- `sensitivity:critical` - Критическая чувствительность

#### 3. Тип данных (data_type)

**Значения:**
- 
- `pii:true` - Персональные идентифицирующие данные
- `phi:true` - Защищённая медицинская информация
- `pci:true` - Данные платёжных карт (если применимо)
- `spii:true` - Особо чувствительные ПДн (ФИО+дата рождения)

#### 4. Срок хранения (retention)

**Значения:**
 
- `retention:1year` - 1 год
- `retention:3years` - 3 года
- `retention:5years` - 5 лет
- `retention:10years` - 10 лет
- `retention:permanent` - Постоянное хранение
- `retention:legal` - Согласно законодательству

#### 5. Источник данных (source)

**Значения:**
 
- `source:patient` - Данные от пациента
- `source:laboratory` - Данные от лаборатории
- `source:doctor` - Данные от врача
- `source:system` - Системные данные
- `source:external` - Внешний источник

#### 6. Юрисдикция (jurisdiction)

**Значения:**
- 
- `jurisdiction:ru` - Российская Федерация
- `jurisdiction:eu` - Европейский союз (если применимо)
- `jurisdiction:global` - Глобальное

#### 7. Обработка (processing)

**Значения:**
- `processing:encrypt` - Требуется шифрование
- `processing:mask` - Требуется маскирование
- `processing:anonymize` - Требуется обезличивание
- `processing:audit` - Требуется аудит
- `processing:restrict` - Ограниченная обработка

#### 8. Доступ (access)

**Значения:**
 
- `access:rbac` - Контроль доступа на основе ролей
- `access:abac` - Контроль доступа на основе атрибутов
- `access:restricted` - Ограниченный доступ
- `access:need-to-know` - Доступ по принципу "необходимо знать"

## III. Инструменты тегирования

### 1. Microsoft Purview Information Protection (Azure Information Protection)

**Описание**: Решение Microsoft для классификации и защиты данных.

**Возможности:**

- Автоматическая классификация файлов
- Ручное тегирование пользователями
- Защита на основе меток
- Отслеживание использования данных

**Применение:**

- Тегирование файлов Excel, Word, PDF
- Защита файлов на файловом сервере
- Интеграция с Exchange Mail Server

### 2. Apache Atlas

**Описание**: Платформа для управления метаданными и тегирования данных.

**Возможности:**

- Создание таксономий тегов
- Автоматическое тегирование на основе правил
- Отслеживание происхождения данных (Data Lineage)
- Поиск данных по тегам

**Применение:**

- Тегирование данных в будущих БД
- Управление метаданными для Data Lake
- Отслеживание потоков данных

### 3. Varonis Data Classification

**Описание**: Решение для автоматической классификации и защиты данных.

**Возможности:**

- Автоматическое обнаружение ПДн
- Классификация на основе содержимого
- Тегирование файлов
- Мониторинг доступа

**Применение:**

- Автоматическое тегирование существующих файлов
- Обнаружение неучтённых ПДн
- Мониторинг доступа к тегированным данным

### 4. Собственное решение на основе файловых атрибутов

**Описание**: Использование расширенных атрибутов файловой системы для хранения тегов.

**Возможности:**

- Хранение тегов в метаданных файлов
- Скрипты для автоматического тегирования
- Интеграция с системами контроля доступа

**Применение:**

- Тегирование файлов на Windows Server
- Интеграция с Active Directory
- Автоматическое применение политик на основе тегов

## V. Управление тегами

### Жизненный цикл тегов

1. **Создание тегов**: При создании или обнаружении данных
2. **Обновление тегов**: При изменении классификации данных
3. **Валидация тегов**: Проверка корректности тегов
4. **Удаление тегов**: При удалении данных (с аудитом)

### Политики тегирования

#### Политика 1: Обязательное тегирование
- Все файлы с ПДн должны быть помечены тегами
- Автоматическая проверка при сохранении файла
- Блокировка сохранения без тегов

#### Политика 2: Автоматическое тегирование
- Автоматическое применение тегов на основе содержимого
- Уведомление пользователя о применённых тегах
- Возможность ручной корректировки

#### Политика 3: Валидация тегов
- Проверка корректности комбинаций тегов
- Предупреждение о конфликтующих тегах
- Автоматическая коррекция некорректных тегов

## VI. Мониторинг и отчётность

### Отчёты по тегам

1. **Отчёт по конфиденциальности**: Количество файлов по уровням конфиденциальности
2. **Отчёт по чувствительности**: Распределение данных по уровням чувствительности
3. **Отчёт по источникам**: Источники данных и их тегирование
4. **Отчёт по срокам хранения**: Данные, требующие удаления

### Алерты на основе тегов

1. **Незащищённые данные**: Данные с тегами `processing:encrypt`, но без шифрования
2. **Несанкционированный доступ**: Попытка доступа к данным с тегами `access:restricted`
3. **Истечение срока хранения**: Данные с истёкшим сроком хранения
4. **Отсутствие тегов**: Данные без тегов конфиденциальности

## VII. Внедрение механизма тегирования

**Этап 1: Подготовка**

- Разработка таксономии тегов
- Выбор инструментов тегирования
- Настройка правил автоматического тегирования

**Этап 2: Пилотное внедрение**

- Тегирование тестовых данных
- Обучение сотрудников
- Сбор обратной связи

**Этап 3: Полное внедрение**

- Тегирование всех существующих данных
- Интеграция с системами защиты
- Мониторинг и оптимизация

**Этап 4: Поддержка**

- Мониторинг использования тегов
- Обновление правил тегирования
- Обучение новых сотрудников
